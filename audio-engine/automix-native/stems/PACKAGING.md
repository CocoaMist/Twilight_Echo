# Windows inference package 2.2

Version 2.1 remains the fixed historical runtime baseline. Version 2.2 changes
the worker and cache management as documented in `MEMORY-2.2.md`, and preserves
all 135 runtime/model binaries and 102 legal notices. The script now copies its
adjacent `worker.py` into the new stage. Only the worker, manifest and inventory
may differ from the verified 2.1 package. The paragraphs below describe the
original 2.1 runtime filtering policy; they are not a claim that 2.2's worker is
unchanged. No further CUDA payload is removed in 2.2.

`package_windows.py` stages and compresses the pinned 2.0 runtime as a smaller
inference-only distribution. The player, material/cache versions, Python,
PyTorch, torchaudio, worker and Demucs checkpoint do not change. Manifest fields
`packageVersion`, `distribution` and `compilerSdkIncluded` describe packaging;
the existing player accepts the package without an application update.

The staging policy omits static/import libraries and debug symbols, compiler
headers/CMake files, dependency tests, type-checker stubs, pip implementation
and generated bytecode. It retains Python import modules used for inference,
distribution metadata and legal notices, and **every DLL, PYD, EXE and TH** from
the source package. In particular, no CUDA DLL or supported GPU architecture
is removed. `torch.testing` is retained; only `test`/`tests` directories are
omitted. This package is intended to run the worker, not build extensions or
install new Python packages.

The staged root is `automix-enhancement`. `package-files.json` records SHA-256
and byte counts for retained files. The inventory excludes itself, archive
metadata and generated bytecode. All original retained files except the
packaging-only `manifest.json` must match their source SHA-256. The stage report
records every omission and its reason.

Example commands (run using Python 3.11, with new staging/output paths):

```powershell
python package_windows.py stage --source D:\source-pack --stage D:\new-stage --report D:\stage-report.json
python package_windows.py 7z --stage D:\new-stage --output D:\enhancement.7z --seven-zip 'C:\Program Files\7-Zip\7z.exe' --report D:\archive-report.json
```

The 7z distribution uses lossless LZMA2, a 64 MiB dictionary, four compression
threads and 512 MiB solid blocks. Use 7-Zip to extract it beside
`TwilightEcho.exe`. A standard DEFLATE level-9 ZIP can instead be produced with
the `zip` action. Both archive actions test the completed archive before
publishing it; they never overwrite a previous output. The pinned model is not
quantized, re-trained, re-serialized or shortened.

For the 2026-10-11 delivery, compare uncached local MP3/FLAC inference with the
2.0 package on CPU/stereo, CUDA/stereo and CPU/mono. Also verify cache reuse,
an actual CUDA allocation failure falling back to CPU, corrupt/missing model,
hard timeout, finite samples and exact original-PCM context. Extract the final
archive into a new empty directory, validate all file digests and run its own
embedded Python from a different working directory. Keep old delivery archives
and installed applications untouched.
