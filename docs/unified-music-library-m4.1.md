# M4.1：歌曲与专辑独立评分

2026-10-24。个人评分已接入原歌曲信息、专辑发行浏览及生产 Core。人工内容、真实桌面、主题／键盘及打包验收仍按用户安排后置。

## 从当前歌曲或具体发行打分

- 原歌曲信息提供录音评分；原专辑页在当前选中的具体发行下提供专辑评分。浏览专辑项目不会把项目当作个人评分目标。
- 歌曲信息以原 Track 的平台和 ID 精确定位物理录音，同名或人工等价播放组不扩大评分范围。专辑评分复用当前发行选择，切换项目资料层仍保留该具体发行，不另建一套评分目标选择。
- 个人评分为 0.5—5 星，以整数 `steps=1..10` 保存。未设值和明确清除分别保留；清除后仍属于“我未评分”。
- 选择星级先形成草稿，保存后重新读取核对；清除是独立操作。失败或评分／身份变化撤下旧值，保留草稿，要求明确重读，不自动重放未确认的写入。
- 评分历史按需分页，记录设置、清除及身份转接的时间和原因。移除来源成员、离线或重启不删除个人值。
- 首次取得评分 revision 只初始化观察；后续评分、身份或曲库变化撤下旧值，Core epoch 变化隔离旧响应和未确认写回。
- 人工播放版本只作为导航，不能直接打分。它可以包含不同录音或物理发行；评分针对底层物理实体，只有确认了同一资料身份才共享。

## 确认身份前解决个人值冲突

未确认时，评分挂在原稳定录音／发行实体；确认后挂在相同类型的共享资料身份上。不同压片、现场／翻唱录音及项目层次不自动共用评分。

关联预览显示当前条目和目标身份的个人值：

1. 目标无值时可把当前值带入共享身份，保留原实体记录。
2. 两边值相同直接共享，不重写已有值。
3. 两边不同（包括明确清除与星级的冲突），必须选择采用当前、采用目标或清除目标。选择携带评分 revision，过期须重新比较。
4. 自动确认及专辑子项自动确认遇到冲突留待复核。历史关联恢复复用同一规则；评分迁移、身份、任务及审计同事务提交，后续失败全部回滚。

解除关联后恢复原实体范围的评分；共享期间新写的值留在共享身份，不自动复制给拆出的来源。原记录及历史均保留。

## 资料评分先固定含义，再启用真实来源

`musicRatingSources.ts` 定义并校验供应商、原生目标、编辑／社区机制、原值、量程、明确换算规则、票数、时间、出处及使用范围。

- 只有可信部署配置明确批准的规则才能换算，例如 0—100 除以 20、1—5 原值。不按量程猜换算，不平均不同供应商。
- `personal / base / effective` 分开；资料源与目标层次明确选择。没有选择资料源时 effective 等同 personal。
- 项目资料分不灌入具体发行或歌曲分；个人半星约束不强加给资料分。比较保留原精度，3.96 不进入“≥4 星”。
- 账号上下文、来源使用范围及过期条件继续生效。

当前没有启用获准的真实评分供应商；详情明确返回“暂无资料评分”。这些纯函数为后续获准来源与 Focus 共用规则，当前不发评分网络请求，不启用 MusicBrainz 社区评分，也不把热度、播放量或识别分数当星级。

## SQLite 23 与生产接线

新增 `personal_ratings_state`、`personal_rating_values`、`personal_rating_history` 及身份变化触发器，使用原音乐库连接与默认 Profile。半星整数约束同时在边界和 SQLite 执行。

升级先创建含已提交 WAL 内容的一致快照，再事务安装 schema 23；失败不推进版本。旧版本迁移 fixtures 同步移除新增评分对象，再验证原数据和回滚。早期 v14 的兼容路径继续保留。不得让旧二进制直接打开 schema 23；回滚使用匹配版本的升级前快照。

- `ratings.targets / detail / history`：`library:read`；`ratings.set`：`library:write`。Profile 由服务端固定，公共请求不接受任意 profileId、目标身份或文件访问能力。
- 原 database worker／client、Core service／application、生产 entry、请求校验与实际 Renderer 调用均已接线。本地评分不要求启用资料源、平台登录或 `providers:call`。
- 值、身份与 token 在同一 SQLite 读快照中取得；写入校验评分总 revision、关联 revision 与目标键，避免跨连接旧值配新 token。
- 持久 `ratings-changed` 事件驱动权限隔离的 `CoreSnapshot.ratingsRevision`。资料或评分变化不改当前播放队列、收藏、平台点赞或原普通歌单。

M5 的便携备份 music 域仍待实施，需要保留原／共享目标键、评分历史及清除记录，并在身份映射后恢复；当前持久化及升级快照不代替便携备份交付。
