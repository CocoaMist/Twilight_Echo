# 播放器第二轮性能修复实施记录（2026-10-05）

已实施第二轮审计发现的六项优化，并补上真实渲染回归发现的歌词视图缓存失效问题，以及原生响度回归发现的 WAV 格式误判。修复前证据与修复后复测分开保存。

## 改动与行为

### 卷积峰值和保护机制

长 IR 改为非均匀分区：小分区处理开头，较大分区利用尾部的时间余量分摊正向 FFT、频域累加、逆 FFT 和输出叠加。尾部任务可在回调之间续算；开头同步 FFT 使用直接循环，避免不必要的续算状态开销。FFT 计划和缓冲在配置时分配，实数信号仅保存半频谱。默认开头分区按采样率为 1024 / 512 / 256 帧，用户指定的分区仍保留；实际延迟通过现有状态返回。

保护预算改为实际回调期限的 80%，预留 20% 给其他处理，删除原有 2 ms 下限。固定容量的时间窗口计数能识别周期性超预算，普通便宜回调不会把证据清零；三次超预算会触发现有退避和旁路机制。重置和重新启用通过历史有效长度排除旧数据，避免逐项清空全部 IR 历史。

正确性验证将长 IR 输出与直接卷积逐样本比较，覆盖多个分区边界、后期输入脉冲、1024 帧及不规则分块、重置后的静音。频域处理的改动不是仅靠耗时测试验收。

### 队列内容与手动选择分离

第一次加载后由主进程签发队列版本。相同内容手动选曲仅发送版本、索引、逻辑 ID 和当前播放路径，主进程重新授权当前路径并检查它与已提交条目匹配，再更新原生游标。CUE 同文件条目依靠索引与逻辑 ID 区分，Play 继续使用正确的片段范围。

内容、顺序、CUE 范围、响度数据改变，或原生服务重启后，重新加载并签发版本；失效版本触发完整检查，不可用伴随条目仍降级为当前曲目。旧版接口缺少选择能力时保留完整加载路径。渲染层仍以轻量队列 JSON 检查内容，保留 O(N) 的内容比较，不声称整个选曲流程变成常数时间。

5000 项连续 13 次选择的行为测试：完整授权批次从每次一次减到总共一次，完整原生加载一次，后续 12 次仅更新游标；每次仍重新检查当前文件。

### 歌词精确失效

播放页和桌面歌词各持有一个当前内容缓存，以原文、翻译、罗马音和 TTML 替换选项决定是否重新解析。歌词显示开关保留稳定引用，合并重复居中监听；桌面全文只在曲目信息、歌词、偏移或加载状态改变时发送，关闭时停止内容计算和待发送时钟。

20 次无关元数据更新以及无关歌词管理文档更新，测试结果均为零次额外解析、零次重居中、零次桌面全文发送。修改歌词仍重新解析和发送，标题修改复用歌词行并更新桌面标题。

真实 Electron 回归还发现：相同歌词跨曲目复用时，行级 `v-memo` 可能复用已卸载父视图中的节点。加入父视图身份作为失效条件，避免切歌后组件更新异常，同时保留歌词内容缓存。

### 授权降级与失败记录

批量授权失败后的单文件降级最多 16 个并发任务，检查请求是否仍为当前选择；被替代的请求停止派发和提交。

分析失败记录上限为 1024，每 64 个请求清理过期记录，访问过期条目立即删除，成功或缓存命中也会删除记录。无需常驻清理定时器；完全空闲时不会主动清空 Map，但保留量有明确上限。

### 可视化传输

原生查询支持 `visualizerBarCount`，直接在 8192 FFT 结果上按原算法生成 140 根 log-Hz 柱条，省略 4096 点 spectrum 及未使用的 spectrogram / oscilloscope。主进程保留旧版绑定的聚合兼容路径，原生柱条也经过数值归一化。逐项回归确认与原算法一致，无播放时返回零柱条。

### WAV 格式误判

完整响度测试发现，周期性很强的 PCM 数据会让 FFmpeg 把合法 WAV 误判为 MPEG-TS。现在读取本地 WAV 的 12 字节容器签名，确认 RIFF / RF64 / RIFX 与 WAVE 后才指定 WAV 解封装器；其他内容继续普通格式探测。已有 CUE 分段、截断、损坏文件和峰值测试负责验证。

## 复测与限制

原生复测参数、两次原始 JSON 和复现命令见 [证据说明](D:/Project/Twilight_Echo/docs/performance-audit-evidence/2026-10-05-round2-fixes/README.md)。同修复前使用 `-O2`；本次卷积预热延长到完整 IR 历史，避免低估稳态工作量。计时不包含真实设备、完整 IPC 或绘制。

| 测量项 | 修复前 | 修复后两次复测 |
| --- | --- | --- |
| 96 kHz、双声道、8 秒 IR，512 次回调峰值 | 8.454 / 6.217 ms；各 32 次超过 2.667 ms 期限 | 1.588 / 2.028 ms；均 512 次活动处理，测量段零次超期 |
| 192 kHz、双声道、0.125 秒 IR，512 次回调峰值 | 2.574 / 1.930 ms；各 32 次超过 1.333 ms 期限 | 0.932 / 1.195 ms；均 512 次活动处理，测量段零次超期 |
| 4096 点频谱与 140 根柱条，原生读取中位数 | 完整频谱在本次复测为 1.982 / 1.571 ms | 柱条为 0.654 / 0.636 ms |
| 同一采样内容的可视化 JSON 字符数 | 13555 | 3228，减少约 76% |
| 同一 5000 项 JSON 重复加载中位数 | 24.210 / 20.681 ms | 0.020 / 0.019 ms；首次解析峰值仍为 23.583 / 20.768 ms |

18 个卷积组合中，两次均有 8 个配置完成整段预热及 512 次活动测量，测量段均无超期；另外 10 个在预热期触发保护旁路。后者的低耗时没有计入改善。预热段仍保留偶发超期，详见原始 `warmupDeadlineMisses`，不将短测量解释为长期零超期保证。

这也有代价：48 kHz、8 声道、0.125 秒短 IR 的峰值从原有 2.359 / 1.760 ms 上升到 2.965 / 3.626 ms，仍低于 5.333 ms 回调期限。分摊长尾和维护多层任务增加了短 IR 的开销，因此本次不声称所有配置都更快。保护因 80% 预算不足而触发，其中也包含尚未超过整个回调期限的配置；多声道长 IR 和高采样率长 IR 仍需要控制配置或继续优化内核。
