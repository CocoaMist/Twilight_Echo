歌单控制器只创建一次，所有 `useMusicStore()` 调用共享相同的缓存、保存队列和权威版本。曲库替换仍递增原有 revision，元数据匹配、收藏查询和音源变更继续据此失效缓存。歌单补丁统一执行保存前快照、更新时间和持久化，保留无变化时不写入的规则。

普通歌单优先解析可播放的本地录音；聚合歌单保留远端音源快照。两者使用同一段录音身份与首选音源匹配逻辑，并通过参数表达各自策略，避免两份本地替换逻辑独立漂移。

## 已合并的重复实现

- 文件分析任务的并发去重、失败冷却、取消代次、完成通知和取消后的缓存回滚。BPM 与响度的缓存键、结果类型及不可用策略仍由各自适配器提供。
- BPM 与响度缓存的版本 1 文档读取、受限 JSON 解析、串行写入、条件回滚、尺寸查询与清空。各自公开方法、旧缓存格式和淘汰规则保留；清空和条目计数的原有时序也保留。
- 主进程与 preload 的播放恢复数据校验，包含版本、模式、位置、队列 revision 和 CUE 边界；兼容旧的可选队列字段。
- 设置层与实际输出的音频配置归一化。设置仍允许保存 8192 帧，实际引擎仍默认限制为 2048 帧；缺省设置对象也保留原来的可选字段形态。
- CUE 与歌词的 GB18030 四字节检测；电台与播客的 HTTP/HTTPS 网址校验；DSP 资产与 VST3 的流式 SHA-256 文件哈希。
- 艺术家与流派的分组投影、歌单空快照处理、两份播放队列的 BPM 更新与清除、投送地址的相同分类分支。

对 `src` 下非测试、非声明 TypeScript 的函数及类方法做了重复扫描：用 TypeScript printer 去注释、归一化空白，比较长度大于 250 字符的完整函数体。扫描前存在 6 组完全相同的实现，处理后为 0 组。这是明确重复体的检查，不是对 Vue、原生 C++、脚本或近似克隆的全面无冗余证明。

- Windows `pnpm run test:product` 的 19 个套件全部通过，包含保存冲突恢复、录音身份、聚合歌单音源保留、播放路由、取消后的缓存回滚、歌词、插件、网络源、DSP 与既有行为测试。
- 新增 15 个可执行回归用例，覆盖原生/软件 A–B 循环、投送地址与直播位置、BPM 请求去重及失败重试、两种输出缓冲上限和共享播放恢复校验。原有静态检查改为检查实际模块归属和返回方法，保留行为套件。
- 第二轮新增 7 项缓存回归：BPM 和响度均验证并发写入不丢条目、版本 1 文件可重新读取、新写入不被过期回滚删除、写入失败后可以恢复；另外验证响度不可用结果不作为缓存命中。缓存、分析管理器和真实本地 FTP 协议服务的定向测试共 36 项通过。
- `pnpm run lint`、完整 Node/Web 类型检查、`pnpm run build` 和渲染资源预算通过，预算阈值没有调整。
- `pnpm run test:quality-policy` 29 项通过；没有更改 Windows 验证策略或删除测试入口。
- VST3 bridge 原生回归编译并通过（2048 参数传输与处理音频）。运行进程的 `W64DEVKIT_ROOT` 指向本机已有的 WinLibs MinGW 编译器目录；没有安装工具链或修改持久环境变量。
