## 已合并的重复实现

- 文件分析任务的并发去重、失败冷却、取消代次、完成通知和取消后的缓存回滚。BPM 与响度的缓存键、结果类型及不可用策略仍由各自适配器提供。
- BPM 与响度缓存的版本 1 文档读取、受限 JSON 解析、串行写入、条件回滚、尺寸查询与清空。各自公开方法、旧缓存格式和淘汰规则保留；清空和条目计数的原有时序也保留。
- 字体目录从两次 PowerShell 启动合并为一次，并发请求共享在途查询；成功结果缓存，失败或空结果允许重试，清空后的旧查询不能覆盖新目录。保留系统与用户字体、Unicode 解析及原有 IPC 接口。
- 主进程与 preload 的播放恢复数据校验，包含版本、模式、位置、队列 revision 和 CUE 边界；兼容旧的可选队列字段。
- 设置层与实际输出的音频配置归一化。设置仍允许保存 8192 帧，实际引擎仍默认限制为 2048 帧；缺省设置对象也保留原来的可选字段形态。
- CUE 与歌词的 GB18030 四字节检测；电台与播客的 HTTP/HTTPS 网址校验；DSP 资产与 VST3 的流式 SHA-256 文件哈希。
- 艺术家与流派的分组投影、歌单空快照处理、两份播放队列的 BPM 更新与清除、投送地址的相同分类分支。

对 `src` 下非测试、非声明 TypeScript 的函数及类方法做了重复扫描：用 TypeScript printer 去注释、归一化空白，比较长度大于 250 字符的完整函数体。扫描前存在 6 组完全相同的实现，处理后为 0 组。这是明确重复体的检查，不是对 Vue、原生 C++、脚本或近似克隆的全面无冗余证明。

### node-forge 新披露漏洞

最新生产审计新增 GHSA-86w9-cpqp-85rv（CVE-2026-85393）。实际依赖仍是 node-forge 1.4.0；官方 npm 尚未发布修复版本，GitHub advisory 的 `first_patched_version` 为 null。没有写入不存在的 1.4.1 override。

本地补丁回补上游 [PR #1152](https://github.com/digitalbazaar/forge/pull/1152) 的嵌套 DigestAlgorithm 元素数防护，固定来源 `ceba34402e329f0365134f23fe19898756527d65`。该 PR 尚未合并，不将它描述为正式发布。安装策略强制补丁声明、文件、来源以及锁文件 SHA-256 绑定，NCM 必须解析到带 `patch_hash` 的依赖；缺声明、缺文件和错误哈希均被拒绝。

生产审计原有入口新增真实回归：官方攻击向量在安装补丁后被拒绝；隔离子进程仅在内存移除此防护后接受同一向量。该上游向量关闭 padding 检查来单独验证嵌套 ASN.1 防护；正常签名使用默认严格模式，并验证可选 NULL 参数和错误摘要。NCM 的 RSA NONE 结果与 Node 原生加密一致，weapi 双 AES、eapi 和 linuxapi 实际往返通过。

设置真实 candidate 后，生产审计 12 项全部通过且无跳过，NCM 登录补丁仍有效。仅为这个已经绑定并验证的本地补丁增加一项有说明的审计例外，正式修复发布后应升级并删除补丁和例外。有效审计门禁为 moderate/high/critical=0；registry 的原始 metadata 仍按未修复版本报告 high=3，未将原始计数描述为零。锁文件变化后再次运行真实 10,000 条重复检测基准并刷新认证存档，预算和防篡改检查保持原样。
