# Echora 全界面评估与统一 HIG 方案

> 评估日期：2026-09-30。对象：Twilight Echo 主仓库当前界面。阶段：评估与方案，尚未实施界面重构。

> 后续状态：该方案的首轮修复已实施，见 [Fluent 2 界面修复记录](fluent2-ui-repair-2026-09-30.md)。本文的缺陷描述与截图保留为实施前的评估记录。

## 1. 结论与决策建议

当前混乱主要来自导航、设置归属、页面骨架和跨窗口表现各自发展。功能数量本身不是唯一问题：同一功能有多个入口、同一个按钮会承担不同语义，页面切换有时改变播放配置，而不同页面的标题、边距、字体、提示方式没有稳定规则。

建议建立一套 **Echora HIG，以 Fluent 2 为布局、字体、组件与反馈的基础**。先修正行为，再迁移公共骨架，最后整理主题和视觉效果。保留音乐封面、歌词、音效编辑的专业表达，也保留迷你播放器、桌面歌词、托盘控制这些真实使用场景；将它们约束在同一个行为和样式契约中。

优先处理六件事：

1. 返回、菜单、页签只负责导航；不得隐式修改 EQ 模式、丢弃编辑上下文。
2. 本地、网易云、QQ、网络源使用稳定的全局导航，来源切换不再换一套应用外壳。
3. 修复窄窗口设置分区的超宽标签，以及 EQ 工具栏的逐字折行。
4. 音效关闭时仍允许进入编辑器；音效页面始终可暂停、试听和回到当前曲目。
5. 字体、图标、提示栏、按钮、弹窗统一归属和尺度，主题只在允许的范围内覆盖。
6. 建立按窗口可用宽高、系统缩放和多窗口场景验收的矩阵。

本报告完整保留上一轮九项意见（UI-01～UI-09），再加入播放、小尺寸、卫星窗口和统一 HIG 的评估。

## 2. 评估基线与证据边界

### 2.1 使用的版本

- 主仓库：`D:/AIGC/3017-Echora/Twilight_Echo`，采样时分支 `main`，HEAD `344fb03`，package 版本 `1.2.1`。
- 评估包括采样时的工作区改动；本轮未修改应用源码，未覆盖另一个对话的逻辑检查改动。
- 主进程、预加载和渲染层在隔离目录从当前源码重新构建，构建成功。原生音频二进制复用了本机已有 1.2.4 资源，没有重新编译 C++；因此播放结果属于“当前应用源码 + 已有原生二进制”的组合验证。
- 原生测试使用独立用户目录。原有音乐库和正式登录目录未替换。网易云测试登录由用户扫码完成；QQ 外部 Provider 0.3.1 在隔离目录启用，但用户反馈无法登录，本轮按用户要求停止 QQ 登录尝试。

### 2.3 本轮已完成的真实操作

网易云登录成功；个性化推荐、个人音乐库、云盘均加载真实数据。选择推荐曲目后，播放进度从起点推进到约 0:32；暂停后可定位到 1:30，主播放页、迷你播放器均显示这一位置。迷你播放器可返回主窗口，桌面歌词能够显示同一首歌的实际歌词。未以浏览器示例播放冒充真实播放。用户反馈当时没有留意声音，因此本轮未确认可听性；设备切换、无缝播放、音质和长期稳定性尚未完成验收。

QQ 登录失败目前是用户反馈与评估阻塞，**不在本报告中推断为账号、网络、插件或平台的某一确定原因**。

## 5. 目标信息架构与导航 HIG

### 5.1 稳定外壳

建议一条全局导航：**首页、音乐库、歌单、最近播放、音乐来源**。设置、声音工作台、扩展、账号作为固定工具入口。音乐库内再选择歌曲/艺术家/专辑/流派/文件夹；音乐来源里选择网易云、QQ、电台/播客、网络源。来源切换显示“当前范围”，不替换全局外壳。

首页可按默认来源展示内容；“我的歌单”统一列出本地与跨来源歌单。聚合能力以歌单来源和合并规则表达，保留“跨来源歌单”筛选和快捷入口，避免同一功能有两套浏览状态。

### 5.2 导航规则

| 操作            | 统一语义                                                           |
| --------------- | ------------------------------------------------------------------ |
| 菜单按钮        | 只展开/收起导航，不退出当前页面、不改播放配置                      |
| 选择目的地      | 到新的一级/二级目的地，保存可恢复上下文                            |

| Esc             | 关闭最上层可关闭表面；有草稿按草稿规则处理；不退出应用、不停止播放 |

## 6. 统一布局与分辨率策略

### 6.1 采用 Fluent 布局原则

Fluent Layout 提供间距、网格、断点和重排原则；Echora 是可缩放的桌面窗口，应以 **CSS/DIP 可用窗口宽高** 决定布局，不能按“显示器是 1080p/4K”硬编码。系统缩放使相同物理分辨率对应不同逻辑空间，任务栏和窗口边框也会减少可用高度。

Fluent Web 的参考断点为 320、480、640、1024、1366、1920；桌面应用主窗口无需因此支持手机宽度，迷你/托盘/遥控各有自身边界。主窗口当前常规最小尺寸约 760×692，实际还受工作区约束；本方案的低高度样本用于压力评估。

### 6.2 四种页面骨架

| 骨架   | 页面                         | 固定内容与滚动                                                              |
| ------ | ---------------------------- | --------------------------------------------------------------------------- |
| 浏览页 | 首页、歌曲、集合、来源、搜索 | 全局标题栏+导航+公共 PageHeader；内容一个主要纵向滚动区；底部播放条预留空间 |
| 设置页 | 九分区、账号配置             | 公共分区导航+可搜索表单；分区选择与内容滚动联动；无横向整页滚动             |
| 工作台 | DSP、EQ、主题、扩展          | 公共页头/主操作/状态栏；辅助面板按窗口重排；核心编辑区保持可用宽度          |
| 沉浸页 | 正在播放、可视化             | 统一返回、封面与歌词内容、可到达的传输控制；歌词滚动独立且不吞主导航键      |

### 6.3 项目建议尺度（以下数值是方案目标，不是 Fluent 强制值）

- 基础间距使用 4px 网格；常用 4/8/12/16/20/24/32/40/48。图标内部对齐可使用 Fluent 2/6/10 例外，页面边距不再随意产生 13/27/37 等新尺度。
- 标题栏统一高度，至少沿用当前 32 DIP 控件条；正文从安全区开始。标准页头 56～72 DIP，紧凑页头 48～56 DIP。
- 侧栏常规 200～224 DIP，展开/抽屉用同一组值；EQ 仅两个类型不需独立 240 DIP 侧栏。
- 页边距：紧凑 16、中等 24、宽屏 32。正文阅读/设置上限约 960～1120 DIP；丰富首页约 1280～1440 DIP，宽屏可以增加卡片列数。
- 卡片间距 16/24，卡片内部 16/24；圆角按控件 4～8、卡片 8～12、浮层 12～16 分级。胶囊只用于短状态/分段选择等有明确语义的场合。
- 桌面常规点击目标建议 32×32 DIP，主要播放按钮 44×44 或更大，紧凑工具最低建议 28×28。移动遥控目标至少 44×44。44/48 的触控要求不能机械套在所有桌面字母索引上，但必须提供键盘和可发现的替代方式。
- 主播放栏常规 72～88 DIP，紧凑 64～72 DIP；内容底部预留播放条+16 DIP，不能通过浮层遮住最后一行。

## 7. 统一字体、图标、颜色与主题

### 7.1 字体契约

默认 UI 字体建议 Windows 使用 `Segoe UI Variable / Segoe UI`，中文使用 `Microsoft YaHei UI` 或明确的统一 CJK 回退；跨平台使用平台系统字体。若产品最终选择 Inter+MiSans，也必须作为一个全局产品字体决策，统一应用到主窗口、小窗、托盘和弹窗，不能由页面自行选。

将“系统字体”真正映射为系统字体；“跟随主题”单列为显式选择。已设置自定义字体的用户不应被重置。字体优先级建议：**用户显式 UI 字体 → 产品默认/系统字体**；主题字体只在用户主动允许跟随主题时覆盖。

| 语义角色              | 字号/行高参考                               | 用途                                            |
| --------------------- | ------------------------------------------- | ----------------------------------------------- |
| Caption               | 12/16                                       | 次级格式、路径、时间、计数                      |
| Body                  | 14/20                                       | 表单、列表、正文、消息正文                      |
| BodyStrong / Subtitle | 16/22，适度半粗                             | 重要行标题、小分区                              |
| Section               | 20/26，半粗                                 | 内容分组标题                                    |
| PageTitle             | 24/32 或 28/36，半粗                        | 页面标题，避免不同页随意从 20 到 48 跳变        |
| Hero                  | 32/40，最多必要时 40/52                     | 宽屏首页焦点；短窗口降级为 PageTitle            |
| Numeric/technical     | 继承对应字号，等宽仅用于需要对齐的数值/诊断 | 播放时间、频率/增益、详细诊断                   |
| LyricsContent         | 独立歌词字号与行距                          | 主歌词/桌面歌词可大字；工具栏不继承歌词装饰字体 |

上表基于 Fluent Web 字阶取适合本产品的子集。10px 字阶不作为常规中文标签默认，11/13/15/17 等现有页面比例先迁移到语义角色。歌词原文、译文、音译分别有稳定大小关系；较小译文仍需实际可读，不能只靠模糊和降透明度表达层级。

### 7.2 图标与状态

统一一套界面图标语言，优先 Fluent 风格。不同平台品牌图标保留。普通图标 16/20 DIP，导航 20 DIP，主播放 20/24 DIP；容器点击目标与图标尺寸分开。

所有纯图标按钮都有可访问名称与 Tooltip；字形字符不能充当名称。选中、禁用、错误不能只靠颜色，使用文字/图标/轮廓补充。焦点环使用公共 token，不能被主题透明度覆盖掉。

颜色使用语义 token：背景、表面、边框、主文本、次文本、品牌、成功、警告、错误、选中、焦点。正常文本对比度目标至少 4.5:1，大文本至少 3:1；歌词背景叠封面、透明桌面和玻璃模式必须分别验证。高对比度时允许使用系统颜色与不透明表面。

### 7.3 主题边界

主题可改变配色、材质、封面/歌词内容表现、有限圆角和动画强度；不得重定义导航语义、字体可读性底线、错误提示位置、返回行为、主操作顺序和点击目标。

外观设置保留“当前主题、浅/深/系统、UI 字体、文本大小、减少动画、窗口表现”等用户偏好；详细主题编辑集中到工作室。迷你与桌面歌词允许独立样式，但默认使用“跟随应用”，覆盖时有清楚的“此窗口独立设置”标记和恢复继承按钮。

## 8. 统一提示栏、通知与弹窗

已有全局 Notice Store 应继续复用，补足规范与跨窗口分发，不必推倒重建。

| 类型           | 放置/持续方式                   | 示例                               | 交互                                                           |

| Dialog         | 仅阻断决策或有损操作            | 重置配置、删除歌单、离开未保存草稿 | 明确对象与范围，主次按钮固定；焦点进入、Esc/关闭、焦点恢复一致 |
| Status/Tooltip | 就近表达，不冒充通知            | DSP 旁路、歌词延迟、独占模式待命   | 状态本身不反复弹 Toast，必要时打开详细说明                     |

Toast 最多 4 条，间距参考 16 DIP。超过数量合并到任务/通知入口。错误不以“6 秒后消失”为唯一提示；避免同一故障在全局 Toast、页内错误和弹窗同时重复。

MessageBar 位于内容区工具栏下或对应容器标题下，不覆盖全局侧栏。警告/错误带可执行按钮或说明链接；长消息展开后完整换行，超过两行时操作移到下方。多条状态按错误、警告、成功、信息排序，可折叠为带数量的状态组。关闭只隐藏说明，不代表问题已解决；未解决问题在相关后续会话重新提示，解决后自动消除。

依据 Fluent Toast 对 intent 和辅助播报的要求，信息型使用低打扰播报；阻断性错误按语义及时播报并保留页面说明。不得把所有错误都固定为 polite，也不应把所有成功事件都升级成抢占播报。具体 role/aria-live 必须结合消息类型与焦点实现验收。

跨窗口反馈优先出现在发起动作的窗口：迷你窗口的修改在小窗反馈；主窗口后台任务进入主任务区；桌面歌词内容错误在歌词状态和主歌词管理中可找回。不能为了提示而抢焦点、弹出主窗口或遮住播放控制。

统一措辞：“发生了什么 + 对当前操作的影响 + 可执行下一步”。例如“网易云登录已过期，重新登录后可继续加载收藏”，按钮“重新登录”；避免“Error 301”、裸异常、重复“操作失败”和内部 IPC/主进程描述。

## 9. 播放与独立窗口专项规范

### 9.1 播放语义

- 全局一个当前曲目、队列、播放位置和播放模式。主播放栏、首页卡片、迷你、托盘、SMTC/遥控均是同一会话的视图。
- 行主操作按用户单击/双击偏好执行；右键和“更多”不启动播放。播放全部/随机播放明确是否替换队列；加入队列、设为下一首明确是否改变当前曲目。
- 来源不可播放、会员限制、连接失败、设备不可用分开提示。显示歌曲信息不表示已经可播放；实际成功由播放状态确认。
- Seek 拖动显示预览位置，完成后提交；加载、跳转中、暂停、播放的按钮/状态一致。未知时长/直播不显示可拖动假进度。
- 调整 EQ/DSP 的“修改草稿、应用试听、保存预设”是不同操作。现有立即生效项目如保留，应显式显示“即时生效”且可撤销，不与主题草稿混淆。
- 切换页面、主窗↔小窗、开启/关闭歌词不得停止当前播放、创建新队列或丢失位置。关闭窗口行为只使用一处权威设置。

### 9.2 迷你播放器

最小模式展示歌名/艺人、播放暂停/切曲、进度和返回完整播放器；音质、封面、歌词按空间逐级增加。420×220 不把全量控制挤成 10px 文本。锁定、置顶、自定义、最小化入口在悬停/键盘焦点时可发现；返回不能只依赖不可解释的图标。

自定义面板使用公共导航/表单 token；立即修改须提供撤销。默认字体跟随应用，主题切换不改播放会话。浮窗位置按当前显示器工作区限界，断开显示器后恢复到可见区域。

### 9.3 桌面歌词

继续共享歌词会话、偏移和播放时钟。区分“等待播放、获取中、没有歌词、歌词获取失败、纯音乐”：没有歌词不能一律称为纯音乐。主、迷你、桌面显示同一歌词内容，展示行数/翻译/音译可以不同。

锁定/穿透必须有可靠解锁路径：托盘菜单、可用快捷键、已有悬停解锁能力都保留，不能仅靠记住快捷键。原生位置和任务栏窗口不能越过可用工作区。亮/暗复杂桌面均需可读；暂停隐藏与暂停保留由一个清楚设置控制。

任务栏模式、自动隐藏任务栏、Windows 多显示器、顶部/侧边任务栏若平台允许、100～200% 缩放、超长双语歌词与逐字歌词单独验收；本轮未把默认双行成功扩展为全部模式成功。

### 9.4 托盘、系统与遥控

托盘弹出控制保留轻量定位，主题和字体默认继承。系统媒体控件与任务栏缩略图使用系统规范，保证曲目/播放状态正确。局域网遥控保持触控尺度、明确连接与配对状态；本轮没有为视觉检查开启新网络服务。

## 11. 验收方案与可交付标准

### 11.1 需要固定的测试素材与状态

使用短/长中英文歌曲名、无封面、未知元数据、无歌词、双语/逐字歌词、直播无时长、空库/空历史/空搜索、失败/重试、数千首歌曲和较长队列。网易云与 QQ 分别测试未登录、二维码准备/有效/过期/扫码待确认、成功、失效和接口失败；不能用一个平台替代另一个。

### 11.2 必须验收的矩阵

| 维度          | 组合                                                                                                                           |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 主窗口        | 760×692、1024×600 压力、1280×688 压力、1366×768、1920×1080、2560×1440；另外按真实物理 1080p/2K/4K 与系统缩放换算后的工作区实测 |
| 系统缩放      | 100%、125%、150%、175%、200%；双屏不同 DPI、窗口跨屏、断开副屏                                                                 |

| 播放          | 本地/网易云/QQ/网络/电台/播客；播放暂停、seek、上下首、队列模式、来源切换、窗口切换；输出设备改变/不可用                       |

### 11.3 通过标准

1. 返回、菜单、页签没有隐式音效写入，导航不改变当前播放会话。
2. 同一设置只有一个权威归属；多个入口进入同一个上下文。
3. 主要操作无整页水平滚动、不可见按钮、逐字按钮标签、播放条遮挡；短窗口第一屏能找到主操作和当前内容。
4. 主/迷你/托盘的 UI 字体与公共反馈遵循默认继承；自定义覆盖可解释、可恢复。
5. 同一错误只有一个主反馈位置，重要错误持续可恢复；不会用“空内容”掩盖加载失败。
6. 播放页、调音页和独立窗口的控制可达，曲目、位置、歌词与状态一致；可听性由真实音频确认。
7. 提供按页面/窗口记录的截图、实际测试尺寸与 DPI、步骤、结果、失败记录。自动化布局检查与原生实测分别记录，不以构建通过代替体验验收。

本轮是上述验收矩阵的基线评估，并非全量发布验收。尚未完成的项已明确列出，后续实施按阶段关闭，不将“未发现横向溢出”记录为整页通过。
