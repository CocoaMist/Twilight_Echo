# 界面材质语言 · 第一版

Twilight Echo 的界面材质由透色的玻璃体、弧面的边缘和有方向的光组成。目标是让紧凑控件具有体积与层次，同时保留现有配色、字体、卡片轮廓和 Windows 操作习惯。实现文件和变量使用内部代号，产品界面沿用“液态玻璃”。

## 研究依据

- [Apple HIG Materials](https://developer.apple.com/design/human-interface-guidelines/materials)：玻璃用于浮动控制和导航层，内容保持清晰；常规材质与透亮材质按阅读需求区分。
- [WWDC25 Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/)：阴影、折射与散射共同表现体积，尺寸不同的形体需要不同光学处理。
- [WWDC26 Platforms State of the Union](https://developer.apple.com/videos/play/wwdc2026/102/) 22:43–23:09：新一轮 Liquid Glass 调整强调暗边、局部亮高光以及复杂背景下的扩散。
- [Windows Layering and elevation](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/layering) 与 [Acrylic](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic)：用轮廓和阴影交代层级，并保证透明背景上的可读性。

以上用于建立原则。本应用使用 Web 渲染实现，尚不模拟真实光线追踪或系统原生材质。

## 共同规则

| 层             | 职责                   | 第一版实现                                           |
| -------------- | ---------------------- | ---------------------------------------------------- |
| 透色基底       | 透出背景，稳定文字对比 | 延续已有材质颜色、模糊、折射与用户参数               |
| 弧面肩部       | 表现表面的转折         | 上方 7px 内柔和亮面，下方 4px 内暗面                 |
| 定向边缘       | 表现受光方向           | 局部亮边过渡到透明，再接暗边；避免整圈等亮白线       |
| 表面反光       | 保持高光清晰           | 播放栏实测几何生成的光照图，独立合成在背景扩散之上   |
| 接触与悬浮阴影 | 区分厚度和高度         | 近影 0 2px 5px，远影 0 12px 32px；深浅色使用不同强度 |

基础光影统一放在 `src/renderer/src/assets/bohr.css`。文字和按钮位于光学层上方；光学层不参与布局和命中检测。高光复用现有几何缓存，不在光标移动时逐帧重新生成。圆角轮廓使用原生抗锯齿边框，避免双层遮罩相减造成台阶。

## 清晰度与流畅度

- [Apple 高分辨率渲染指南](https://developer.apple.com/library/archive/documentation/GraphicsAnimation/Conceptual/HighResolutionOSX/Optimizing/Optimizing.html)强调自绘内容匹配屏幕像素密度。Web 内容由 Chromium 自动处理；应用生成的玻璃贴图则必须自行处理采样密度。
- 折射和高光共用采样规则：至少 2 倍采样，随屏幕 DPI 提升至 3 倍；单轴不超过 2048 像素、单张不超过 2097152 像素（解码 RGBA 上限 8 MiB）。超限时等比限制采样，保留光学半径和折射宽度。
- 轮廓像素使用 4 × 4 覆盖率积分，折射图保持全不透明，避免预乘透明度破坏中性色通道。透明内区直接填充，直线边缘复用相同光学结果；保留逐像素抖动，不改变渐变输出。
- 跨显示器 DPI 变化单独监听，即使 CSS 尺寸没有变化也更新贴图。更新仍走原有 120ms 合并调度及各 8 项缓存，不在鼠标移动时生成贴图；缓存按有效尺寸区分并更新使用顺序。
- 歌曲列表的播放描边改用原生圆角边框，保留既有色系与选中状态；歌词行及字符取消长期 `will-change: transform`，由实际动画管理合成生命周期。[Chromium 动画指南](https://web.dev/articles/animations-guide)建议仅在必要时使用该提示；[重采样说明](https://developer.chrome.com/blog/re-rastering-composite)解释了持续缓存与缩放清晰度的取舍。
- 保留硬件加速偏好、字体渲染偏好和现有无障碍回退，不添加全局强制 GPU、MSAA 或 `translateZ(0)` 开关。
- 播放栏轮廓只绘制一次：高光描边不再经过同半径的外层裁切，也不叠加重合的内阴影亮线；封面图片取消自身圆角，由容器统一裁切，包含悬停缩放。重复裁切会相乘边缘覆盖率，提高贴图采样无法修复这一层问题。
- 独立 Electron 像素回归将实际圆角与同几何的单层原生轮廓／图片裁切对比，覆盖深浅色、常规／玻璃／液态玻璃、六档 DPI 和整数／小数坐标的 72 种组合，包含封面静态／悬停状态，共 144 个渲染情形，分别检查四个角。参考使用 Chromium 实际栅格，包含小数高度下的边框像素对齐，不用截图放大插值作为抗锯齿证据。

这些改动以 Windows Electron 的实际渲染验证为准，尚未对 iOS/macOS 原生应用做帧率或视觉等价性比较。

同密度生成基准在 Windows Node 中预热后各运行 7 次，取两张贴图合计的中位耗时：1180 × 72 播放栏约 105 → 12ms，320 × 320 卡片约 100 → 7ms（2 倍采样）。比较对象是逐像素计算与内区／直边复用，两者 RGBA 逐字节一致；不包含 PNG 编码、GPU 合成或整机帧率。

## 使用范围

- **标题栏**：附着于窗口的透色层，无底部描边或硬边阴影；高度仍为 40px。播放页继续沉浸，不叠加浮动玻璃边框。
- **设置导航**：启用液态玻璃时使用常规扩散与统一浮层阴影，优先保证阅读；正文维持原有内容面板。
- **标准播放栏**：独立浮动的透色层，使用弧面与局部反光；保持约 72px 默认高度和既有按钮布局。
- **迷你与紧凑播放栏**：保持独立的平面条带语言，不加入标准播放栏的弧面层。

设置中显示“液态玻璃”，存储值继续使用 `liquidGlass`。既有主题、材质设置和插件接口无需迁移；用户可在背景与界面材质编辑器中选择并预览。

## 回退与验证

关闭模糊、降低特效、减少透明度、高对比度及强制系统颜色时隐藏播放栏光学装饰，沿用可读性回退。关闭材质、关闭高光或卸载后清理反光图与强度，避免残留。

验证包含真实 Electron 深浅色渲染、点击命中、材质切换、无障碍回退与进度拖动。全窗口预览保留设置导航状态，只临时显示原页面；取消恢复原偏好。Windows Computer Use 验证实际播放控件与从设置进入预览的流程。
