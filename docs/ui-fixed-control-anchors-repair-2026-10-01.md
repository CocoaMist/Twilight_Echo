# 固定按钮位置检查与修复

日期：2026-10-01。针对反馈“顶栏左侧返回键导致固定按钮位置变化”，并检查同类条件显示控件。

## 返回键位移已复现

在修复前提交 `a9cb99b` 的真实标题栏和样式上，使用新的坐标比较检查复现了问题。760px 宽度、默认深色页面中，返回区由 0px 展开至 36px：

| 固定按钮 | 返回键出现前 x | 返回键出现后 x |
| --- | --- | --- |
| 菜单 | 0px | 36px |
| 搜索 | 36px | 72px |
| 设置 | 72px | 108px |
| 扩展 | 108px | 144px |

旧代码的宽度动画使移动过程更缓慢，但不能保持位置。右侧窗口按钮没有参与这次位移。

## 修复后的约定

2026-10-02 根据“左侧空缺碍眼”的反馈调整顺序：固定命令组直接从左边缘开始，菜单、搜索、设置和扩展按钮始终位于 x=0、36、72、108px。返回区放在命令组之后，始终保留 36px；有返回路径时只淡入图标，无路径时并入后方的拖拽留白。返回栈增减不移动固定命令，也不再在菜单前制造空缺。左侧按钮组不参与压缩，标题栏仍为 35px，右侧窗口按钮仍为 46×35px。

返回路径消失后，返回区立即进入 `inert` 状态，淡出中的按钮不能再被点击或键盘聚焦。事件处理也检查当前返回路径，防止残留动画节点触发一次多余返回。工坊预览保留相同位置约定，同时继续隔离真实返回栈和原生窗口操作。

## 回归证据

- `pnpm ui:check -- --scope titlebar` 通过。现有场景增加返回坐标比较和三处真实搜索模板的检查，共 35 项行为。
- 144 种宽度、主题、页面组合各记录返回键不存在、淡入、显示、淡出和再次消失时的按钮坐标，共 720 个采样；坐标容差为 0.1px。
- 2026-10-02 增加左侧命令从 x=0 开始、返回区紧跟命令组的检查；没有命令组的模式则从左边缘开始返回区。
- 检查菜单和通知开关不能改变常用按钮坐标；空搜索的隐藏按钮不能占据键盘焦点，输入和清除后宽度保持一致。
- 应用回归 404/404、类型检查、生产构建及渲染体积检查通过。
- 用同一坐标比较器运行修复前的真实标题栏，检查因左侧按钮右移 36px 而失败，确认回归能够识别原问题。
