# Echora UI Lab 开发工具草案

日期：2026-10-01。面向 Echora 开发者及界面维护者。本次交付包含标题栏修复、可运行的检查原型，以及下一阶段开发方案。

## 工具要解决的问题

Echora 的主窗口、主题工坊、播放页和独立播放器共享部分控件，但各自的样式、状态和窗口行为会相互影响。仅检查某一张截图，容易漏掉最大化后的图标、异步状态回包、预览污染真实窗口、主题覆盖和账号切换等问题。

UI Lab 将真实组件放入可重复的本地场景，控制页面状态、宽度和主题，记录行为及几何结果。开发者修复一个问题后，可以用相同场景复查，并把报告交给作者讨论。工具位于开发脚本中，不增加正式产品的导航页面。

## 本轮标题栏修复

| 已确认的问题 | 修复后的行为 | 回归依据 |
| --- | --- | --- |
| 最大化按钮没有读取和订阅原生窗口状态 | 最大化显示“还原窗口”和还原图标；还原后显示“最大化窗口”和方框图标 | 初始状态读取、最大化和还原事件 |
| 初始状态读取可能晚于窗口变化 | 先订阅事件，较晚返回的初始结果不能覆盖新事件 | 延迟回包场景 |
| 工坊预览没有明确使用预览模式 | 预览禁用窗口按钮、不建立原生拖拽区域、不读写真实窗口状态，不继承真实返回栈及标题栏留白 | 禁用按钮、强制派发点击和预览挂载检查 |
| 头像加载失败后，换账号仍不重试 | 用户或头像地址改变时重新尝试加载 | 失败头像和更换账号场景 |
| 通知选中背景引用未定义变量 | 使用现有标题栏悬停颜色变量 | 实际计算背景色 |
| 控件组可能参与压缩 | 窗口按钮组固定尺寸，按钮明确使用 `type="button"` | 多宽度边界和居中检查 |

主窗口标题栏保持 **35 CSS px**；通知、最小化、最大化和关闭按钮保持 **46 × 35 CSS px**，窗口图标保持 **12 × 12 CSS px**。这些数值沿用本项目已经确认的设计约定，并非 Fluent 2 或 Apple HIG 对所有应用的强制尺寸。

托盘播放器的已有回归检查原先可能在入场动画过程中测量图标。本轮调整检查时机：确认初始化完成并结束场景中的动画后再测量，保留产品动画和原有尺寸容差。

## 已实现的检查原型

在仓库根目录运行：

```sh
pnpm ui:check -- --scope titlebar
pnpm ui:check -- --scope navigation
pnpm ui:check -- --scope shell
```

每次运行默认更新 `output/ui-lab/report.json` 及同名日志。用 `--report` 指定其他 JSON 路径可保存不同检查结果。标题栏成功报告还包含独立的场景证据文件。

| 范围 | 当前覆盖 | 运行方式 |
| --- | --- | --- |
| `titlebar` | 原生状态发布及清理；35 项标题栏和搜索行为检查；144 种几何场景及 720 个返回状态采样 | 主进程单元检查与隐藏 Electron 组件场景 |
| `navigation` | 页面切换、返回栈、导航守卫，22 项现有测试 | 复用现有导航测试 |
| `shell` | 标题栏、插件中心按钮、通知抽屉，以及迷你播放器、桌面歌词和托盘控件的既有回归场景 | 复用现有外壳组件测试 |

标题栏场景使用真实 `TitleBar.vue`、真实基础及 Fluent 样式，模拟窗口接口和账号数据。几何矩阵为六档宽度（760、1024、1280、1920、2560、3840 CSS px）× 四种主题组合（默认深色、默认浅色、Obsidian Glass、Paper Light）× 六种状态（默认、设置、流媒体、播放、登录、液态材质）。

每种布局比较返回键不存在、淡入、显示、淡出和再次消失时的常用按钮坐标，共 720 个采样；另外检查菜单及通知开关不能移动按钮。搜索检查使用真实在线歌单工具栏，以及从 `SongList.vue` 提取的两处真实搜索模板和样式，验证清除按钮、输入宽度与操作锚点。曲库搜索场景不包含完整页面的数据加载流程。相关修复见 [固定按钮位置检查](./ui-fixed-control-anchors-repair-2026-10-01.md)。

2026-10-02 补充图标比例检查：左侧命令改用原生 16px Fluent 图标，矩阵同时记录图形自身边界和中心偏移，避免只检查 SVG 画布。其他页面的默认尺寸继续继承原有约定。见 [标题栏图标比例修复](./titlebar-icon-optical-repair-2026-10-02.md)。

同日补充排列约定：菜单直接从左边缘开始，返回区紧跟固定命令组；每个返回状态都检查此顺序，避免固定占位在最左侧造成空缺。

报告包含测试结果、耗时、运行平台、Node 版本、Git 提交、工作区是否有改动及日志路径。标题栏报告另外记录关联源码的 SHA-256，方便确认报告对应哪一版组件。原型尚未为导航和外壳生成同样的几何矩阵或源码哈希。

相关实现入口：

- `scripts/ui-lab.cjs`：限定可运行范围、调用现有测试、输出报告。
- `scripts/ui-lab/titlebar-fixture.mjs`：构建真实组件、模拟状态、测量几何、清理临时场景。
- `src/renderer/src/app/titleBar.behavior.test.ts`：回归测试与开发工具共用同一个场景。
- `src/renderer/src/app/useWindowChrome.ts`：原生状态与标题栏的同步。
- `src/main/app/windowChrome.ts`：从真实窗口发布最大化及还原状态。

工具不添加生产依赖，复用仓库现有 Vue、Vite、Electron 和 Node 测试设施。新回归已经接入 `test:app`，专项工具作为开发入口保留。

## 下一阶段的交互式场景台

建议先围绕标题栏完善交互式场景台，再扩展到插件中心。场景台独立启动，左侧选择组件和场景，中间显示真实组件，右侧展示事件记录、检查结果及源码入口。

第一批控制项包括宽度、主题、页面状态、通知开关、账号状态、返回栈、最大化和还原事件、接口失败及回包延迟。模拟窗口按钮只写入事件记录；开发者可以明确看到一次点击是否重复触发、是否在等待状态确认、是否发生状态回退。

每个场景应保存组件入口、输入状态、事件序列、检查约定及参考规范。失败报告应写明触发步骤、实际值、期望值和关联源码，而不是只显示“视觉不一致”。截图对比作为补充，几何、状态和可访问名称仍需独立检查。

| 阶段 | 开发内容 | 验收条件 |
| --- | --- | --- |
| P0，本轮已实现 | 标题栏场景、专项命令、报告与回归入口 | 三种范围可运行；标题栏异步竞态和预览隔离可重复检查 |
| P1，建议下一步 | 可见场景台、预设场景、事件时间线、失败截图和源码定位 | 从场景入口到失败报告只需一次运行；同一事件序列可重放；所有原生动作都绑定模拟器 |
| P2 | 插件中心与导航场景；迷你播放器及桌面歌词的状态场景；跨页面控件约定 | 每个组件拥有加载、空、成功、失败、禁用及键盘场景；不会为了检查新增产品页面 |
| P3 | Windows 原生窗口检查与发布证据归档 | 明确区分模拟结果和原生证据，保存环境、步骤及结果 |

页面注册表应复用应用真实入口，并连接此前整理的页面逻辑树。多个页面共用的按钮、字体、提示、返回行为和间距约定集中定义，页面检查只声明差异。避免维护另一套与产品脱节的页面实现。

## 设计规范如何进入工具

以 [Fluent 2 Layout](https://fluent2.microsoft.design/layout)、[Fluent 2 Typography](https://fluent2.microsoft.design/typography) 和 [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/) 为参考，延续现有 [统一 HIG 方案](./ui-hig-unification-plan-2026-09-30.md) 及 [Apple Music 与 Fluent 2 质检记录](./ui-quality-review-apple-music-fluent2-2026-09-30.md)。本轮没有重新进行完整的官方规范逐项审查。

工具应将参考原则转为可检查的项目约定：同类按钮的尺寸和状态一致、图标居中、字体层级清晰、主题令牌有定义、反馈能够关闭、返回行为可预测、预览与原生动作隔离。Apple Music 的内容组织和播放连续性作为产品参考；Windows 标题栏动作及项目确认的尺寸仍需遵守本机行为。

后续约定登记需标明来源：官方规范、项目决定或组件特例。每项例外说明原因及适用范围，避免把某个页面的特殊布局变成全局规则。

## 结果与验证边界

本轮专项检查通过：标题栏 3/3、导航 22/22、外壳 1/1；当前标题栏证据包含 35 项行为和 144 种几何场景，补充 720 个返回状态采样。应用回归 404/404 通过，修改源码的代码检查、类型检查及生产构建通过。

宽度矩阵检查的是 CSS 布局，不能代表真实显示器 DPI 缩放。隐藏 Electron 场景没有验证主程序实际拖拽、Windows Snap、跨屏缩放、真实音频或扫码登录。报告明确保留 `nativeDeviceValidation: false`。按本次要求，全程不使用 computer use；这些原生验证留给后续单独执行和记录。

建议下一次开发优先完成标题栏可见场景台和事件重放，再将插件中心的安装、启用、失败恢复、取消和重复点击场景迁入同一工具。这样每次界面修复都可以带上同一格式的复现与回归证据。
