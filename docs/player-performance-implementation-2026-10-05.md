# 播放器性能优化实施记录（2026-10-05）

本次根据播放器性能审计实施优化，保持公开播放 IPC 和队列条目格式兼容。性能数据来自本机隔离测试，音频组件计时不代表真实设备掉音频率。

## 已实施

- **原生倍速处理**：以先前音粒的未加窗重叠片段作为匹配参考；采用多级有界相关搜索，逐声道计算避免反相抵消。修复音粒之间的重叠叠加，使用满足半窗重叠的周期 Hann 窗；输出按 hop 缓存，回调分块不会改变结果。参考和输出缓冲全部在 `prepare()` 分配。短来源和结束尾部可以排空，搜索保留必要历史，切歌在 pull 内触发重置后重新读取当前位置。
- **队列授权**：共享请求内去重和 16 个工作任务的解析器，复用于文件授权与原生队列加载。保留重复曲目、CUE 范围及顺序，不缓存跨请求的授权结果。队列加载等待原生操作完成后才报告成功。
- **封面缓存**：颜色缓存改用 SHA-256 摘要，不持有整个图片字符串作为键；非 Web Crypto 环境直接解码。统一封面与颜色缓存清理，并通过代际检查防止迟到的摘要或封面 IPC 响应重新填充已清空的缓存。
- **可视化**：共享轮询检查窗口可见性、播放状态和消费者需求。隐藏的播放器栏释放消费者。EQ 的频谱、电平和播放器栏复用一份采样，根据需求在 64/2,048 点之间切换；冻结频谱保留显示帧，切换其他 EQ 页签释放需求。
- **歌词**：活动集合成员未变化时保留引用；无障碍文本和静态行信息单独缓存。时间轴使用反向单调栈找到后续第一条更大的时间戳，保持无时间戳、重复和乱序语义。视口缓存行顺序，仅逐帧处理活动动画；起点和终点都远离视口的行直接放到目标位置，避免大幅跳转启动数千个动画。窗口隐藏时完成含延迟的最终目标并停止帧循环。
- **队列快照**：去掉生成快照时对完整曲目的对象展开，增加单版本轻量快照缓存。显式检查路由、顺序、条目身份和显示元数据，兼容原地修改的曲库数据；缓存不持有歌词和匹配载荷。
- **统计观测**：`persistenceStatus.lastFlush` 提供整理、序列化、实际写入、总耗时及字符数。新增 `pnpm run benchmark:listening-stats`，用独立 Chromium 用户目录测量实际 `localStorage`，不读取用户历史。
- **回归门禁**：新增 60 种 WSOLA 性能组合及音频质量、结束和分块一致性用例；收紧队列窗口预算为 8 ms、5k/20k 快照预算为 20/80 ms。发布门禁按 CMake 实际注册数量检查原生测试，兼容新旧 CTest 汇总格式；校正已有门禁自测中过期的阶段计数。

## 测量结果

### 原生音频组件

修复前两轮隔离测试，1.5 倍速、256 帧输出：96 kHz 双声道单次峰值 5.28–6.32 ms，超过 2.67 ms 缓冲期限；192 kHz 双声道峰值 20.89–23.91 ms，8 声道峰值 35.02–45.95 ms，期限为 1.33 ms。

修复后的新基准每个组合预热 16 次、记录 1,024 次回调，覆盖 48/96/192 kHz、2/8 声道、256/1,024 帧以及 0.5/0.75/1/1.5/2 倍速。一次运行中，192 kHz、256 帧、1.5 倍速峰值为双声道 0.149 ms、8 声道 0.304 ms，均无超时。完整矩阵通过门禁；另一个 0.5 倍速组合出现一次 1.605 ms 峰值，因此门禁同时输出超时次数，以 p99.9 的 80% 缓冲预算和最多一次偶发超时作为失败判据。

前后基准的采样次数和输入不完全相同，不用这些数字推算整机 CPU 降幅。原生 CTest 已编译并运行新的正式性能门禁。

### 渲染与主进程

| 场景 | 优化前/重新构建 | 优化后 |
| --- | --- | --- |
| 5,000 个重复来源的队列授权 | 5,000 次解析、最高并发 5,000 | 1 次解析；唯一来源最高 16 并发 |
| 64 张约 1 MiB 封面的颜色缓存键 | 约 64 MiB 字符串；约 64 MiB 堆保留 | 4,096 个摘要字符；隔离测试堆增量 169,296 字节 |
| 20,000 首队列快照 | 本轮重新构建中位 14.00 ms | 校验并复用中位 1.74 ms |
| 60,000 首队列快照 | 本轮重新构建中位 60.17 ms | 校验并复用中位 5.75 ms |
| 10,000 行纯文本时间轴 | 审计中位约 46.46 ms | 本轮中位约 0.16 ms |
| 5,000 行歌词动画 | 所有行逐帧检查 | 测试中活动动画少于 30 行；全部结束后零帧任务 |

颜色缓存测试模拟图片解码，未包含位图内存。快照对比使用同一原始曲目数据，每轮执行 GC；实际 Vue 渲染、磁盘授权耗时和视口布局仍受设备及数据影响。

## 保留的后续事项

真实 Chromium 中，1,000 首统计样本（478,381 字符）保存中位约 4.2 ms；10,000 首样本（4,843,382 字符）约 51.1 ms，其中实际存储写入中位约 27.3 ms。该同步保存仍可能造成长任务。本次按计划只加入测量，异步存储及增量保存需作为独立迁移处理，保留旧历史、导入导出、写入失败重试和退出保存能力。

尚未进行真实 WASAPI/ASIO 设备的持续播放、音频听感对比、整机 CPU/GPU/RSS 长时间采样。倍速优化涉及波形衔接，发布前应重点验证人声、瞬态、多声道、切歌和 seek。普通速度的音频管线维持原来的直通路径。
